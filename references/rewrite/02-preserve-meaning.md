# 02 保意规则 —— 什么绝不能动

> 改写改变的是"怎么说"，不是"说了什么"。本文件是 L1/L2/L3 共同的不可触碰清单。

## 五类不可变内容

| 类别 | 内容 | 核查方法 |
|---|---|---|
| **事实** | 时间、地点、数量、因果、先后顺序 | 逐条对照原文，数量词单独列 |
| **专名** | 人名、地名、作品名、机构名、术语 | 全文检索比对，一字不改 |
| **观点与立场** | 作者的评价、褒贬、价值判断 | 任何"反讽/正话反说"标记原样保留 |
| **结构承诺** | 段落顺序、悬念位置、章节边界 | L3 也不例外（除非用户明确要求） |
| **信息密度** | 每段的信息点数量 | 重写后逐段核对清单，允许换说法不许减条目 |

## 灰色地带的裁决规则

- **模糊表达**：原文故意含糊的地方（"不知道过了多久"）不许替作者说清楚——含糊是修辞。
- **留白**：原文没解释的动机不许补写解释，除非用户点名要求"补细节"。
- **方言/口癖**：角色的非标准语（儿化、方言词、口癖）原样保留，它们是声纹不是错误。
- **病句**：明显的笔误可修，**修前在 diff 报告里列出**；风格性的"错"（短句没标点、句子碎片）是特征，不许修。

## 保意核查流程（每 3 段一次）

1. 从原段提信息点清单（每段 1–5 条）；
2. 在新段中逐条找到对应表达；
3. 找不到的：回炉重写该段；找不到且属于次要修饰 → 在 diff 报告"信息损耗"栏声明，交付时提示用户。

## 自检

- 随机抽 3 个数字、2 个专名、1 个观点句，在产出中定位——定位不到就停交付。
- 改写产出的 `audit_style.py` 报告里，若"信息结构"与原文无法对齐，降级为 L3 流程重做。
