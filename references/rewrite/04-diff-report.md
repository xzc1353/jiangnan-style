# 04 改写报告格式 —— diff_style.py 的输出规范

> 每次改写（L1/L2/L3）交付时必须附报告。机器可读版由 `diff_style.py` 生成 JSON；本文件定义报告的**人读版**结构。

## 报告结构（按序）

```markdown
# 改写报告

## 0. 任务参数
- 手术级别：L2（默认）｜ 触发理由：原文句长方差小 + 负向词 17 处
- 原文：N 字 → 产出：M 字（±x%）

## 1. 体检对比（audit_style 前后对照）
| 指标 | 原文 | 产出 | 目标区 | 判定 |
|---|---|---|---|---|
| M1 平均句长 | ... | ... | ... | ✓/✗ |

## 2. 改动维度摘要
- A 类套话清除：n 处（列举 3 例：原句 → 改句）
- C 类翻译腔：n 处 …
- E 类节奏重排：n 段

## 3. 信息保真核查
- 信息点总数：a ｜ 保留：b ｜ 损耗：c（逐条列出损耗项及理由）
- 专名核对：✓（列出全部专名）

## 4. 风险与提示
- 例：第 7 段原为反讽，改写后语气转正，请确认是否接受。

## 5. 红线
- overlap_check：✓ 无 ≥15 字重合
- 铁律自检：1✓ 2✓ … 8✓
```

## 硬性规则

1. **"信息保真核查"任何一项不通过 = 不许交付**。
2. "风险与提示"不许为空——没有风险就写"无，但请注意 L2 可能弱化原文的 X 风格"。
3. 改动例句每类至少给 1 例，让用户能抽查风格是否达标。
4. 报告与产出文本一起交付，不许事后补。
