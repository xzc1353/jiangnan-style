# 江南文风写作引擎 · 架构规划稿

> 状态：目录骨架已创建，本文件是**设计蓝图**，用于在写正文规则前先对齐结构。
> 版本：v0.1-draft ｜ 日期：2026-11-06

---

## 一、这个 skill 要解决什么

| 能力 | 输入 | 输出 | 关键约束 |
|---|---|---|---|
| **A. 生成** | 一句设定 / 大纲 / 场景要求 | 江南文风的原创文本 | 不抄原作句子；人物默认原创，不默认写同人 |
| **B. 改写** | 任意已存在的文本 | 保留原意的"江南腔"版本 | 不许改掉事实、观点、情节；只动表达层 |
| **C. 续写** | 前文片段 | 风格接续的后文 | 沿用前文的人称、时态、称谓 |
| **D. 诊断** | 一段文本 | 风格体检报告（像不像、哪里不像、怎么改） | 只诊断不改写，除非用户要求 |

真正的难点不是"写得像"，而是**像得有分寸**：江南的辨识度来自几个很具体的机械动作（短句单段、把情绪翻译成动作、用食物和天气承载回忆），而不是"青春疼痛"这种笼统标签。所以整个架构围绕一件事：**把"感觉"拆成可执行、可检查的规则**。

**非目标（明确不做）**：不做代写枪手流水线；不做"绕过 AI 检测"工具；不内置任何原作全文。

## 二、三层架构

```
第 1 层  路由层    SKILL.md
         只回答三个问题：现在是什么任务？该读哪几个文件？必须遵守哪几条铁律？
         目标体积 < 2500 字，永远只加载这一份。

第 2 层  知识层    references/
         文风知识按"骨架 / 皮肤 / 适配 / 改写 / 红线"五类切分，按需读取，互不污染。
         目的是让"写校园短篇"和"改公号文章"加载完全不同的子集，不浪费上下文。

第 3 层  执行层    workflows/ + scripts/ + assets/
         workflows 是逐步 SOP（人和 AI 都能照做）；
         scripts 是可量化、可重复的确定性动作（审计、diff、查重）；
         assets 是模板与评分表，直接进产物。
```

之所以把 `workflows/` 从 `references/` 里拆出来：**知识是"知道什么"，流程是"先做什么后做什么"**。混在一个文件里，改流程会误伤知识，加知识会拖慢流程。

## 四、两条主链路

**A. 生成链**
```
任务路由 → 读 style/（01→02→09，按需 03~08）
        → 读 adapters/genres/<题材> + adapters/forms/<体裁>
        → 走 workflows/wf-generate.md
        → audit_style.py 自审 → 不达标则定点重写（不整篇重来）
        → overlap_check.py 过一遍 → 交付
```

**B. 改写链**
```
任务路由 → 先跑 audit_style.py 拿到原文指纹（像不像、差在哪）
        → workflows/wf-rewrite.md 定手术级别（句 / 段 / 篇）
        → 读 rewrite/01~03
        → 分段改（每段改完立刻做保意核查，不攒到最后）
        → diff_style.py 出对照报告
        → overlap_check.py 确认没引入原文片段 → 交付
```

关键差异：**生成是从零铺，改写是先诊断再动刀**。两条链共用 `style/` 和 `adapters/`，但改写的入口必须先是"体检"而不是"直接重写"——否则会把原文的意思改没了。

## 五、适配性怎么保证

两个正交轴，避免"每个题材都写一份风格说明"这种组合爆炸：

|  | 短篇 | 中篇 | 连载 | 片段 | 非虚构 |
|---|---|---|---|---|---|
| 校园 |  |  |  |  |  |
| 都市 |  |  |  |  |  |
| 东方奇幻 |  |  |  |  |  |
| 科幻 |  |  |  |  |  |
| 回忆散文 |  |  |  |  |  |

`style/` 提供不变的"骨与皮"，`genres/` 只管"这个世界里能出现什么"，`forms/` 只管"这个长度上节奏怎么排"。新增题材只需加一个 adapter 文件 + 在 `00-INDEX.md` 登记一行，不动核心。

## 六、"像不像"要能量化

`style/09-dna.md` 定义指标，`scripts/audit_style.py` 负责算。共 12 项（M7 比喻取材域为分布型，不参与阈值判定）：

1. 平均句长 + 短句（<12 字）占比
2. 单句成段的比例
3. 对话行占比 + 对话平均长度
4. 每千字比喻数
5. 比喻取材域分布（机械 / 光 / 食物 / 天气 / 宗教 / 身体）
6. 第一人称 vs 第三人称占比
7. 问号、感叹号、省略号密度
8. 四字格密度与"的"字密度
9. 段落句数分布（是否出现"长铺陈 + 一句收"）

阈值分两档：**目标区间**（参照原作实测，只存数值不存原文）与**容忍区间**。所有数值在写 `09-dna.md` 之前先留空，跑 `extract_epub.py` + 统计脚本实测后填入——不凭印象填数字。

## 七、版权与合规策略（这是架构的一部分，不是附件）

三条硬规则，写进 `.gitignore`、`NOTICE.md`、`docs/CONTRIBUTING.md` 三处，互相兜底：

1. **仓库永不包含原作正文**。`references/` 里的所有内容都是"分析结论"（句法规律、结构描述、意象分类），不是摘录。要举例就**自己写一句**，不引用原句。
2. **语料只在本地**。`corpus/` 整个目录 gitignore；`extract_epub.py` 只输出到本地，不产生可提交产物。别人 clone 下来拿到的是"工具 + 说明书"，不是"书"。
3. **产物可查重**。`overlap_check.py` 让使用者用自己的本地语料自查，报最长公共子串。这不只是自证清白，也防止模型"背"出原文。

法律定位：**文风本身不受著作权保护，受保护的是具体表达**。所以这条路（抽象规则 + 原创示例 + 查重工具）是干净的；而"把原作喂进去存成知识库随仓库分发"不是。

另外两条写在 `guardrails/fanfic-policy.md`：同人可写但需标注"非官方同人、非商用"；不得产出冒充江南本人新作的文本。

## 八、渐进式加载的预算分配

| 层级 | 体积目标 | 何时加载 |
|---|---|---|
| `SKILL.md` | < 2500 字 | 永远 |
| `00-INDEX.md` | < 800 字 | 路由后立刻 |
| `style/` 单文件 | 800–1500 字 | 按需，通常读 2–4 个 |
| `adapters/` 单文件 | 500–900 字 | 按需，通常读 2 个 |
| `workflows/` 单文件 | 600–1200 字 | 每次任务读 1 个 |
| `scripts/` | 不读进上下文 | 直接执行 |

单次任务典型加载量控制在 **8k–12k 字**，不把整个风格库塞进上下文。

## 十、需要你拍板的几点

1. **名字**：`jiangnan-style`（中性，GitHub 上好搜）还是 `longzu-writer`（有辨识度但绑定单作）？
2. **同人模式要不要内置**？我倾向"内置但默认关闭"，写龙族同人时额外提示合规。
3. **改写强度默认档**：默认"段落级重铸"（明显变味但保内容），还是默认"句级微调"（保守）？
4. **审计要不要卡阈值**？即分数不达标就自动重写，还是只提示不拦截。
5. **首发仓库形态**：只放 skill，还是顺手带一个本地网页 demo（粘贴文本 → 输出改写 + 评分报告）？
