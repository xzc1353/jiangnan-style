# WF 诊断 —— 只出报告，不改文

> 前置：用户意图是"像不像""打个分""问题在哪"，**不要求改写**。
> 铁律：**本流程的产物是报告，不是新文本。** 除非用户明确追加"顺便帮我改"。
> 擅自改写会让用户失去判断基准——他本来想知道现状。

## Step 1 · 机器体检（12 项，客观）

```bash
python scripts/audit_style.py <目标文本> --json
```

逐项对照 `references/style/09-dna.md` 的目标区间与容忍区间，得到三档判定：`OK` / `OUT_OF_TARGET`（在容忍区内）/ `OUT_OF_RANGE`（超界）。

**只报超界项与边缘项**，达标的不要罗列——诊断报告的价值在指出问题，不在念指标。

## Step 2 · 人工评分（9 维，主观）

按 `assets/rubric/style-scorecard.md` 打分。**单样本自评不是盲测**，报告里必须写明："本评分为非盲测单人评分，仅作参考；盲测需混入干扰样本由多人独立打分。"

每维给分时必须带一句具体依据（引用原文片段，≤15 字），否则这一维不算数。给不出依据的维度标"无法判断"，不要填中间分糊过去。

## Step 3 · 定级

综合机器与人工结论，落到三档之一：

| 档 | 判据 | 结论话术 |
|---|---|---|
| **接近** | 机器 ≤2 项超界 且 人工总分 ≥65 | "结构上像，剩下的是点状问题" |
| **偏离** | 机器 3–6 项超界 或 人工 50–64 | "骨架在，皮肤不对"或"皮肤对，骨架散"——要指出是哪一头 |
| **不像** | 机器 >6 项超界 或 人工 <50 | "不是文风问题，是体裁或写法问题"——并说明根源 |

**不许给"60 分，还行"这种无信息量的结论。** 三档必须明确选一个。

## Step 4 · 三条最优先改法（本流程最有价值的部分）

只给三条，按优先级排。每条必须：

1. **指到具体位置**：引原文 ≤15 字 + 说明在第几段；
2. **说清病灶**：违反哪条铁律或哪项指标超界多少；
3. **给可执行动作**：不是"注意节奏"，而是"这一段 137 字一句，在'但是'前断开，断点后补一个≤8 字的短句收尾"。

给第四条就是失败——超出三条，用户不会改。

## Step 5 · 报告格式

```
【诊断报告】
判级：偏离（骨架在，皮肤不对）
机器体检：12 项中 4 项超界 —— 平均句长 68 字（目标 33–52）/ 单句成段 21%（目标 60–78%）/
          比喻 0.2 千字（目标 1.4–2.6）/ 感叹号 11.3 千字（目标 1.0–2.6）
人工评分：58 / 100（非盲测单人）——节奏 4、情绪处理 5、对话 7、画面感 6、比喻 3、少年感 6、群像 5、克制度 3、无违和 8
三条最优先改法：
  1. …（位置 / 病灶 / 动作）
  2. …
  3. …
未处理的结构性问题：结尾第 7 段主角独自总结心迹，属"结论式收尾"，改则动结构，需你确认后另开改写流程。
```

## 常见失败模式

| 症状 | 病根 | 处方 |
|---|---|---|
| 报告全是术语 | 只念指标不给动作 | 每条改法必须有"在哪、改什么、怎么改" |
| 用户看完不知道干啥 | 给了七条建议 | 砍到三条 |
| 顺手改了文 | 越权 | 全回退，只留报告 |
| 分数虚高 | 维度给分无原文依据 | 每维必须引原文片段 |
